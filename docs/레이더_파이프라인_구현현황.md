# 레이더 처리 파이프라인 — 1차 구현

## 구현한 모듈

- `ultrasonic.c/.h`: 센서 Trigger 및 Echo 상승/하강 시각 상태 머신. 보드의 GPIO/FTM 입력 캡처 어댑터가 콜백을 연결해야 함
- `radar_scan.c/.h`: 서보 이동 → 정착 대기 → 측정 → 샘플 저장 → 왕복 이동. 각도는 밀리도
- `distance_filter.c/.h`: 유효 샘플에 대한 이동평균 (최대 9개)
- `background_filter.c/.h`: 각도 bin별 고정 배경 거리 및 차분 판정
- `target_detector.c/.h`: 각도 정렬 및 인접 각도/거리 기반 연속 관측 그룹화
- `target_tracker.c/.h`: 최대 5개 ID의 최근접 각도·거리 매칭, NEW/TRACKING/LOST
- `target_selector.c/.h`: ADC 0~max를 1~5 ID로 양자화, 히스테리시스

## PC 테스트

```bash
bash tests/run_pipeline_tests.sh
```

검증할 시나리오: Trigger 펄스, Echo 거리 환산/Timeout, 스캔 30→60→90→60→30도, 평균 필터, 배경 차분, 후보 2개 그룹, 표적 ID 재연결, ADC 선택.

## 범용성·한계

- 하드웨어 포트와 채널은 실보드 어댑터에서 선택·설정. 이 파이프라인은 특정 FTM/GPIO/LPIT 채널을 직접 점유하지 않음
- `Ultrasonic_Update`의 Trigger 펄스 종료는 **메인 루프 호출 간격의 지터**를 받으므로 실기기에서는 LPIT 원샷 GPIO-low 콜백 또는 출력 비교 하드웨어로 보장해야 함
- Echo 캡처에는 같은 1MHz 시간 기준이 필요. 타임스탬프를 ISR과 메인에서 공유하면 원자성·경합·시간 래핑을 검토해야 함
- Scan은 최신 샘플 1개만 보유하며 소비하기 전에 다음 측정이 완료되면 덮어씀. 보드 통합에서 링 버퍼 또는 처리 주기 제약 필요
- 센서가 Timeout으로 끝난 경우 하드웨어 어댑터의 상태도 정리하여 다음 Start를 허용해야 함
- `target_detector`는 각도 기준으로 정렬하므로 **동일 완전 스캔 프레임의 관측값만 입력**해야 함. 왕복 관측이나 다른 시각 프레임을 섞으면 잘못 묶일 수 있음
- Tracker는 최초 5개 슬롯을 사용하며 LOST 후 매칭은 가능하지만 **오래된 LOST 슬롯의 재할당 기능은 아직 없음**. 교차 시 ID 보장도 없음
- 배경은 자동 학습하지 않으며, 명시적 Calibrate 호출로 기준값을 등록하는 1차 버전
- 거리 온도 보정, 좌표/FPU 연산, 프로파일러, OLED/LCD 통합, 실제 보드 FTM Capture/핀 확인은 다음 단계
- 제공된 값들은 시연용 예시이지 실측된 임계값이 아님

## 시스템에 연결하는 순서

(1) 보드 구성 확정 및 FTM Echo/Trigger 드라이버 → (2) `RadarScan`의 callbacks 연결 → (3) 유효 샘플 Filter/BackgroundMap → (4) 스캔 프레임 끝에서 Detector/Tracker → (5) Selector/Aim/OLED.
