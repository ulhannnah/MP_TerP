# 레이더 표적 수 운용 정책 및 검증 계획

작성일: 2026-11-24  
프로젝트: MP_TerP / S32K144 초음파 레이더  
적용 브랜치: `jun_GPT`

## 1. 결정 사항

- **1차 기본 운용 표적 수: 최대 3개**
- **내부 Tracker의 최대 지원 표적 수: 기존 5개 유지**
- 실제 보드 검증은 **1개 → 2개 → 3개** 순으로 확대한다.
- 4~5개 동시 추적은 확장 기능으로 유지하며, 시뮬레이션 및 하드웨어 성능 평가 후 활성화 여부를 결정한다.
- 이 정책은 **운용·시험 목표**이며, 현재 C 소스의 `TRACKER_MAX_TARGETS = 5`나 `TargetSelector`의 선택 구간을 즉시 변경한다는 뜻이 아니다.

## 2. 판단 근거

### 스캔 조건

현재 가상 테스트의 기준 설정:

| 항목 | 값 |
|---|---|
| 스캔 범위 | 30°~150° (총 120°) |
| 각도 측정 간격 | 5° |
| 편도 스캔 측정 지점 | 25개 |
| 현재 최대 Tracker ID | 1~5 |

균등 간격으로 표적을 배치할 경우 **5개는 약 24°**, **3개는 약 40°** 간격으로 놓는 예시를 구성할 수 있다. 이 간격은 단순 배치 예시이며, 센서의 실제 각도 분해능이나 보장 가능한 표적 분리 각도를 뜻하지 않는다.

### 중요한 제약: 표적 개수보다는 분리 가능성

- 초음파 센서의 빔폭, 표적 크기·형태, 거리, 반사 특성 및 각도 차이가 검출 성능에 영향을 준다.
- 충분히 떨어진 표적 5개보다, 가까이 붙은 표적 2개가 더 분리하기 어려울 수 있다.
- 따라서 표적 수를 3개로 제한하더라도 **군집 병합이나 ID 스위치 문제가 자동으로 해결되는 것은 아니다**.
- 현재 `TargetDetector` 및 `TargetTracker`는 거리/각도 기반 군집화·매칭이므로 가까워지거나 교차할 때 취약하다.

## 3. 현재 실험에서 확인된 사항

아래는 사용자 PC에서 실행한 **실제 C 알고리즘 연동 Python 시뮬레이션** 결과이다. 물리 보드 실측 성능이 아니다.

| 테스트 | 결과 | 해석 |
|---|---|---|
| `static` 고정 2개 | 12회 편도 스캔 중 최초 1회 보정, 이후 11회 후보 2개 및 ID 유지 | 기본 탐지/추적 경로 확인 |
| `moving` 이동 2개 | TP 26, FP 0, FN 4, F1 **92.86%** | 시뮬레이션 조건에서 기본 추적 동작 |
| `moving` 각도/거리 | 각도 MAE **1.35°**, 근사 중심거리 MAE **59.62 mm** | 230 mm 반지름 보정 가정이 포함된 값 |
| `moving` ID 연속성 | 연속 스캔 ID Switch **1회** | 가까워지는 표적에서 추적 안정성 한계 |
| `moving` 후보 병합 | 12~16번째 스캔 후보 1개로 감소 | 표적이 가까워진 뒤 분리 실패 현상 |
| `crossing` 교차 2개 | 9~12번째 스캔 후보 1개, 13번째 이후 2개 | 교차 구간의 후보 병합·ID 교환 가능성 |
| `five` 최대 표적 | 기존 기본 테스트에서 동시 활성 ID 최대 **5개** 확인 | 최대 지원 슬롯이 동작한다는 뜻이며 정확도 보증 아님 |

`crossing`의 정량 평가 결과(F1, ID Switch 등)는 이 기록 시점에 확인되지 않았으므로 확정 수치로 적지 않는다.

## 4. 운용 정책

### 기본 모드: 3개

- 표적 ID 1~3을 실물 시연의 목표로 삼는다.
- 가변저항을 이용한 선택 UI도 3개 운용에 맞추는 방안을 검토한다.
- 초기에 표적끼리 충분한 각도 차이가 있도록 배치한다.
- 단, 현재 `TargetSelector`가 **5개 ID**를 전제로 하므로 사용자 인터페이스를 변경하려면 해당 코드와 표시 동작을 함께 수정해야 한다.

### 확장 모드: 5개

- 기존 `TRACKER_MAX_TARGETS = 5` 및 관련 C 소스를 보존한다.
- 별도 시뮬레이션에서 4~5개 표적의 거리/각도 분리, 오검출, ID Switch 등을 정량 평가한다.
- 자원 제약보다는 **초음파 공간 분해능·군집화·추적 일관성**을 우선 평가한다.
- 실제 4~5개 표적 운용은 3개 실물 검증이 안정적으로 끝난 후 고려한다.

## 5. 2026-11-25 보드 테스트 계획

1. 진단용 `main.c`를 실행해 Smoke Test PASS 확인.
2. LPIT/GPIO/ADC/서보/초음파 등 주변장치를 **단계별로** 검증한다. MCU 핀 허용 전압과 모터 전원·드라이버 확인 전에는 직접 연결하지 않는다.
3. 빈 배경에서 한 편도 스캔으로 초기 배경 보정.
4. 고정 표적 **1개**를 서로 다른 각도·거리에서 검출.
5. 고정 표적 **2개**를 충분히 떨어뜨려 검출 및 ID 유지 확인.
6. 고정 표적 **3개**를 배치하고 ID 1~3 선택·화면 표시·조준 명령 경로 검증.
7. 각도 차이를 단계적으로 좁히면서 **언제 두 표적이 한 후보로 합쳐지는지** 기록.
8. 표적 이동·가림·교차를 수행하고 누락 및 ID 변경을 기록.
9. 4~5개 표적은 3개 운용 안정성 확보 후 별도 확장 실험으로 진행.

**주의:** 현재 저장소의 `src/main.c`는 진단 메인이다. 보드 전체 레이더용 메인과 실제 핀·클록·IRQ 설정은 아직 별도로 준비·검증해야 한다. 3개 정책을 문서화하는 것만으로 실제 UI/Tracker 설정이 변경되지는 않는다.

## 6. 정량 평가 방향

보드 테스트 전후 다음 지표를 기록한다.

- Precision, Recall, F1 / TP·FP·FN
- 검출 각도 MAE, 거리 MAE
- 연속 스캔 ID Switch 수
- 가림 후 재검출·ID 재할당
- 두 표적의 최소 분리 가능 각도(거리 조건별)
- 한 편도 스캔 소요 시간, 각도 샘플 유효율 및 Echo timeout 비율

실험 조건(거리, 표적 크기, 센서 모델, 센서 잡음, 각도 간격, 표적 간격)을 함께 남긴다. Python 모형의 `metrics.json`은 합성 데이터 기반의 상대 평가이며, 보드 실측과 직접 동일시하지 않는다.

## 7. 최종 결론

> **실물 시연 목표는 3개로 줄이되, 구현 상한 5개는 유지한다.**  
> 표적 수 감소는 시스템 시험을 단순화하는 조치이며, 가까운 표적의 군집 병합·ID Switch 문제는 별도 알고리즘 개선 과제로 관리한다.

## 8. 코드 적용 현황 (2026-11-24)

정책을 실제 C 코드에 반영했다. **기본 App 모드는 3개이고**, 선택적으로 5개 모드를 지정할 수 있다.

| 파일 | 반영 내용 |
|---|---|
| `src/header/app.h` | `AppConfig.operating_target_limit` 추가. 0은 3개 기본값, 1~5는 명시적 상한 |
| `src/app.c` | `App_Init()`에서 Selector, Tracker, OLED를 동일한 상한으로 설정 |
| `src/target_selector.c/.h` | ADC 범위를 ID 1~3 또는 ID 1~5로 분할하는 `TargetSelector_InitWithLimit` 추가 |
| `src/target_tracker.c/.h` | `TargetTracker_SetLimit` 추가. 새 ID 할당/갱신/조회는 활성 슬롯으로 제한 |
| `src/radar_renderer.c/.h` | OLED 표적 ID 표시 상한 추가 |
| `tests/test_target_modes.c` | ADC 전체 범위·Tracker 모드별 슬롯 테스트 |
| `sim/test_target_modes.py` | Windows에서 GCC로 테스트 C 소스 실행 |

### 기본 운용 (3개)

```c
AppConfig config = {0};
/* ... 실제 보드 구성 채우기 ... */
config.operating_target_limit = 0u; /* 0 == default 3; 명시적으로 3u도 가능 */
```

### 확장 운용 (5개)

```c
config.operating_target_limit = 5u;
```

모드 설정은 **초기화 시점에만 적용**한다. 현재 `TargetTracker_SetLimit`은 활성/LOST 슬롯이 있는 동안 모드 변경을 거부한다. 별도 런타임 전환 UI는 구현하지 않았다. **Tracker의 물리 저장 공간은 여전히 5개**이다. `TargetSelector_Init` 단독 사용의 기존 5개 동작은 유지한다.

### 현재 검증

S32DS의 기존 빌드 및 C 기반 가상 시뮬레이터 6/6 PASS 기록은 **이번 수정 이전 결과**이다. 새 모드 구현은 소스 반영 상태이며, 이번 수정판의 컴파일과 회귀 테스트, 보드 검증을 다시 수행해야 한다.

PowerShell (`dev` 환경):

```powershell
git switch jun_GPT
git pull --ff-only origin jun_GPT
python sim/test_target_modes.py
python sim/selftest.py
```

`sim/selftest.py`의 기존 5개 표적 시나리오는 **standalone Tracker 기본 5개 기능**을 시험한다. 실제 `App_Init` 3개 설정 경로는 `tests/test_integration.c`에도 별도 검증을 추가했다. S32DS에서는 전체 `src` 및 `src/header` 변경을 반영해 다시 빌드해야 한다.

**주의:** `main.c`는 여전히 안전한 진단 메인으로, 실제 서보·초음파·모터를 구동하지 않는다. `BoardSystemConfig`의 실물 핀맵/타이머 배정은 계속 미확정이다.
