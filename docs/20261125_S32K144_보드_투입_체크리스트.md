# S32K144 보드 투입 전 Bring-up 계획 (2026-11-25)

대상: `jun_GPT`, S32DS 프로젝트 `week11`.
목적: **보드 없이 검증한 C 레이더 알고리즘을 실제 주변장치와 단계별 연결**한다.
현재 검증: S32DS 전체 빌드 오류·경고 0건(사용자 실측 로그), C-backed Python 기본 6/6 시나리오 PASS(사용자 실측 로그).
**실제 보드 실행·전원·Pin MUX·파형은 미검증**이다. 이 문서는 하드웨어 구동 완료를 의미하지 않는다.

## 0. 작업 전 소스 고정

1. `git switch jun_GPT`, `git pull --ff-only origin jun_GPT`.
2. 사용한 커밋 SHA를 기록: `git rev-parse --short HEAD`.
3. S32DS에서 `src/*.c` 및 `src/header` 경로 동기화. 다른 `main()`과 `MP_TERP_USE_EXAMPLE_MAIN`을 동시에 활성화하지 않기.
4. 먼저 기존 **안전한 `src/main.c` 진단 메인**으로 빌드한다. 이 메인은 모터/초음파/GPIO를 직접 켜지 않는다.
5. 소스·옵션·로그를 수정할 때 날짜와 함께 보관한다. 보드 설정 전에 펌웨어 전체 동작을 승인하지 않는다.

## 1. 전원 및 핀 매핑표 작성 (실물 매뉴얼과 회로도 필수)

아래는 **빈 입력 양식**이다. 특정 S32K144EVB 핀이나 확장 보드 배선을 추정해서 채우지 않는다.

| 기능 | MCU PORT/Pin | ALT 또는 ADC/FTM 채널 | 실제 커넥터/전압 | 확인 |
|---|---|---|---|---|
| LPIT 1ms Tick | 내부 | LPIT0 CH__ | 클록 PCS__, Hz__ | [ ] |
| Servo PWM | PORT__/PT__ | FTM__ CH__ ALT__ | 신호전압__, 전원__, GND | [ ] |
| Ultrasonic Trigger | PORT__/PT__ | GPIO | HIGH 전압__, TRIG 폭__ | [ ] |
| Ultrasonic Echo | PORT__/PT__ | FTM__ CH__ ALT__ | Echo 최대 V__, 전압변환기__ | [ ] |
| Stepper IN1~IN4 | 4개 기입 | GPIO | 별도 드라이버/모터 전원 | [ ] |
| ADC Pot | PORT__/PT__ | ADC__ 채널__ | Vref__, Pot 출력 범위__ | [ ] |
| OLED SDA/SCL | PORT__/PT__ | LPI2C__ ALT__ | I2C 풀업 및 로직 전압 | [ ] |
| LCD | 핀/인터페이스 별도 | 병렬 4bit/I2C 확정 | LCD 모델·전압 | [ ] |
| Button | PORT__/PT__ | PORT IRQ | Pull-up/active low | [ ] |
| LED(모의 동작) | PORT__/PT__ | GPIO | 저항/active polarity | [ ] |

- **Echo가 5 V 출력인 모듈**은 S32K144의 입력 허용 전압/핀 유형을 확인하기 전에는 연결하지 않는다. 호환 가능한 레벨 시프터/분압을 검토한다.
- 보드 전원과 서보·스텝 모터 전원 용량을 확인한다. 모터를 MCU GPIO에서 직접 구동하지 않는다. 전원 분리 여부 및 공통 GND 확인.
- FTM 인스턴스는 카운터/모드/분주비를 공유한다. **서보 PWM과 Echo Input Capture는 다른 FTM 인스턴스**로 예약한다.
- LPIT 채널은 시스템 Tick, 스텝 모터, 초음파 Trigger에 각각 독립 배정한다.
- FTMs/PORT ISR 벡터 이름은 **프로젝트의 startup/vector 파일**에 있는 실제 이름을 사용한다.

## 2. 단계별 구동 순서 / 통과 기준

### Stage A: 코드 실행 (외부 구동기 연결하지 않음)

- S32DS Debug Configuration에서 연결된 실제 디버거(OpenSDA/PEmicro 등)를 선택. Flash/Debug 성공 확인.
- 기존 `main.c`를 실행한 뒤 Expressions에 다음 변수 등록.
  - `g_mp_terp_smoke_signature == 0x50415353` (PASS)
  - `g_mp_terp_smoke_result == 0`
  - `g_mp_terp_smoke_stage == 6`
- 예상치 불일치면 다음 스테이지로 진행하지 않고 복귀. 펌웨어 빌드 성공과 실제 실행은 구분.
- 디버거가 없다면 LED나 UART를 추가한 별도 **진단 펌웨어**가 필요하며, 현재 `main.c`에 LED 출력은 없다.

### Stage B: 클록·LPIT

- `SOSC_init_8MHz() → SPLL_init_160MHz() → NormalRUNmode_80MHz()`의 실제 외부 오실레이터/보드 설정 확인.
- `TimerManager_Init()`에서 PCC PCS와 `clock_hz`가 실제 소스 주파수와 일치하도록 설정.
- 디버거 Expressions에서 `TimerManager_GetTickMs()`를 관찰하며 1초에 약 1000 증가 확인.
- 선택한 LPIT IRQ가 startup 코드와 충돌하거나 다른 초기화 함수에 의해 재설정되지 않는지 확인.

### Stage C: 출력 전 단계 (센서·모터 없이)

- LED GPIO가 안전한 출력인 경우에만 500ms 단위 토글. **Launcher는 LED 시뮬레이션 전용**, 실제 발사 기구 연결 금지.
- ADC Pot: 입력 전압의 최솟값/최댓값 및 `ADCChannel_Poll()` 결과 확인. 범위는 설정된 ADC 해상도와 `adc_max`가 일치해야 함.
- OLED: I2C SDA/SCL 파형 및 ACK 확인. 기본 포트 설정 `LPI2C0 PTA2/PTA3`은 **실제 배선이 일치할 때만** 사용.
- LCD 모델 확인 후 `lcd_write` 콜백 연결. I2C 백팩은 `lcd_hd44780.c`의 4-bit 병렬 드라이버와 호환되지 않음.

### Stage D: 서보 PWM (기계 간섭 제거)

- 서보 모터를 연결하기 전에 오실로스코프/로직 분석기로 FTM PWM 주기·펄스폭·ALT 핀 확인.
- 예: 일반적인 서보는 약 20ms 주기를 사용하지만 **해당 서보 데이터시트 값 우선**.
- 전원 용량·기계적 스토퍼·중립각 검증 후 저속, 좁은 각도 범위부터 확대.
- `ServoConfig`의 min/max pulse, min/max angle과 실제 연결 구조를 확인.

### Stage E: 초음파 (모터 전원 제외)

- Trigger GPIO에 지정된 `trigger_us` 펄스 확인.
- Echo 핀 전압부터 확인하고, 레벨 호환 확인 후 FTM Input Capture 입력 연결.
- 선택한 FTM channel pair IRQ가 `BoardSystem_OnEchoCaptureIrq()`로 전달되는지 확인.
- 고정 거리 물체에 대해 mm 측정값·타임아웃·0/무효 구분 확인. 여러 거리에서 측정하여 속도 환산/카운터 오버플로·분주 설정 검증.
- 초음파 응답과 LPIT Trigger 타이머를 단독 검증한 다음 스캔 FSM에 연결한다.

### Stage F: 스텝 모터 (분리된 기계 장치)

- 스텝 드라이버의 IN1~IN4 순서·전압·전류·모터 정격 확인. 출력은 드라이버에만 연결.
- 저속에서 1~8 step 이동 후 방향/배선 확인.
- 원점은 소프트웨어가 **자동 탐지하지 않는다**. 물리적인 기준 위치를 확정한 후 `StepperController_SetHome()` 호출.
- `steps_per_revolution`은 실제 기어비와 HALF/FULL Step 방식에 따라 보정.
- 엔코더가 없으므로 명령한 각도는 실측 회전각이 아니라 **오픈 루프 추정값**이다.

### Stage G: 전체 앱 통합

- `BoardSystemConfig`를 실물 배선에 맞춰 작성한 **별도 보드 설정 소스**를 만들어 `BoardSystem_Init`을 호출한다.
- 현재 `src/main.c`는 **진단 메인**이므로 자동으로 `BoardSystem_Init()`하지 않는다.
- LCD/OLED/LED/GPIO/FTM/LPIT 충돌을 확인한 뒤 `BoardSystem_Update()`를 빠르게 반복 호출한다.
- 최초 한 편도 스캔은 **빈 배경**에서 보정해야 한다. 보정 도중 표적을 두면 배경으로 학습됨.
- 실제 표적 1개 → 2개 → 5개, 정지 → 이동 → 교차, 가림/재등장 순으로 확대.
- 조준용 스텝 모터는 실제 원점 확인 전 움직이지 않도록 유지. 모의 버튼/LED만 사용.

## 3. 실행이 가능하다는 것과 안전하게 동작한다는 것은 다름

- `src/main.c`: **알고리즘 Smoke Test** 전용.
- `src/main_example.c`: `MP_TERP_USE_EXAMPLE_MAIN` 매크로를 켠 경우에만 메인 제공, `MP_TERP_GetBoardConfig()` 구현 필요.
- `BoardSystem_Init()`은 실제 GPIO/FTM/ADC/OLED를 초기화하고 서보 이동·Echo를 시작할 수 있으므로, **미검증 핀 설정으로 호출하면 안 됨**.
- 고장 시 해당 단계의 전원·펌웨어 설정을 차단하고 전 단계로 복귀한다. GPIO HIGH/LOW, 센서/모터 기본 상태를 기록한다.

## 5. 현재 알려진 통합 위험

1. `RadarProcessing`은 단일 편도 스캔 기반이고, 한 번의 초기 배경 보정 결과가 이후 측정에 직접 영향을 미침.
2. `TargetTracker`는 거리/각도 탐욕 매칭: 교차·가림 상황에서 ID 연속성 보장 없음.
3. `UltrasonicPort`의 실물 FTM 입력 캡처/모드·IRQ는 아직 검증되지 않음.
4. `BoardSystemConfig`는 하드웨어 모델/핀맵과 타이머 분주를 모두 요구함. 현재 특정 보드의 확정 설정 파일 없음.
5. OLED/LCD 지연 때문에 스캔 타이밍과 초음파 Echo 처리에 영향을 줄 수 있음.
6. 센서가 장시간 Echo를 반환하지 않을 때의 상태 복구를 반드시 실기기에서 확인해야 함.

하드웨어 모듈과 회로도가 제공되면 이 표를 채워 `board_config.c`와 단계별 하드웨어 테스트 펌웨어를 안전하게 구성할 수 있다.
