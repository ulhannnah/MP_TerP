# 2026-11-25 S32K144 전체 테스트 Main 기준 IO 핀 설정 현황

- 프로젝트: `MP_TerP`
- GitHub 브랜치: `jun_GPT`
- 확인한 소스: `src/main_all_test.c`, `src/main.c`, `src/main_stage.c`, `src/board_config_user_template.c`, `src/header/board_system.h`, 각 주변장치 설정 헤더 및 `src/oled_port_s32k144.c`
- 문서 기준일: **2026-11-25**
- 목적: **현재 코드에서 정해진 신호와 미정인 실제 MCU 핀을 정확히 구분**하고, 실물 배선이 확인되면 그대로 핀맵을 채울 수 있게 한다.

> **현 상태 결론:** `main_all_test.c`에는 실제 MCU 핀 번호가 직접 지정되어 있지 않다. `BoardSystemConfig`로 전달하도록 설계되어 있으나 `board_config_user_template.c`는 모든 값을 0으로 초기화한 뒤 `false`를 반환한다. 따라서 **서보·초음파·Stepper·ADC·LCD·LED·버튼의 실제 IO 핀 배치는 아직 확정되어 있지 않다.** 유일하게 코드에 구체적으로 적힌 물리 핀 예시는 **OLED의 기본 LPI2C0 PTA2(SDA), PTA3(SCL)**이며, 이 역시 실물 배선 확인 전까지 확정값으로 간주하지 않는다.

## 1. 어떤 main이 실제로 실행되는가?

| 전처리기 Symbols | 실행 진입점 | 하드웨어 IO |
|---|---|---|
| `MP_TERP_ALL_TEST_MAIN` 미정의, `MP_TERP_STAGE_MAIN` 미정의 | `src/main.c` | 주변장치 IO **사용하지 않음**. 알고리즘 Smoke Test 후 NOP 반복 |
| `MP_TERP_ALL_TEST_MAIN` 정의 | `src/main_all_test.c` | 실물 핀맵·클록·LCD 설정 검증 후, 여러 주변장치 동시 테스트 |
| `MP_TERP_STAGE_MAIN` 및 `MP_TERP_STAGE=1..5` | `src/main_stage.c` | 선택한 단계만 활성화 |
| `MP_TERP_USE_EXAMPLE_MAIN` | `src/main_example.c` | 선택형 예제. 다른 main과 중복 활성화 금지 |

**전체 테스트 main 활성화 필수 심볼**:

```text
MP_TERP_ALL_TEST_MAIN
MP_TERP_USE_BOARD_CONFIG_TEMPLATE
```

단, `MP_TERP_CONFIRM_PINMAP`이 **없으면** 전체 테스트 메인은 주변장치를 초기화하지 않고 `g_all_error=3`, `g_all_state=0xDEAD`로 정지한다. 이 보호 심볼은 실제 배선을 검증한 경우에만 추가한다.

```text
MP_TERP_CONFIRM_PINMAP
```

위 심볼을 넣어도 템플릿 함수 `MP_TERP_GetBoardConfig()`와 `MP_TERP_AllTestLCDInit()`의 기본 반환값이 `false`이므로, **현 소스 그대로는 실제 주변장치 구동이 시작되지 않는다.** 템플릿에 검증된 값을 채우고 LCD 초기화를 구현해야 한다.

## 2. 현재 IO 핀 배치표 — 실제 번호 확인 현황

| 기능 | 방향 | MCU 인터페이스 | 현재 소스의 실제 핀 번호 | 설정 구조체·필드 | 동작/확인 사항 |
|---|---|---|---|---|---|
| Servo PWM | 출력 | FTM PWM | **미지정** | `s_cfg.servo.port/pin/pin_alt/ftm/channel` | 초기 각도 PWM 발생 가능. Servo와 Echo에 다른 FTM 사용 |
| Ultrasonic TRIG | 출력 | GPIO | **미지정** | `s_cfg.ultrasonic.trigger_port/trigger_gpio/trigger_pin` | 약 100ms마다 측정 시작. `trigger_us` 폭 필요 |
| Ultrasonic ECHO | 입력 | FTM Input Capture | **미지정** | `s_cfg.ultrasonic.echo_port/echo_pin/echo_pin_alt/ftm/ftm_channel` | 입력 전압 및 FTM 채널쌍 IRQ 확인 필요 |
| Stepper IN1 | 출력 | GPIO | **미지정** | `s_cfg.stepper_pins[0]` | 드라이버 IN1에 연결, 모터에 직접 연결 금지 |
| Stepper IN2 | 출력 | GPIO | **미지정** | `s_cfg.stepper_pins[1]` | 드라이버 IN2 |
| Stepper IN3 | 출력 | GPIO | **미지정** | `s_cfg.stepper_pins[2]` | 드라이버 IN3 |
| Stepper IN4 | 출력 | GPIO | **미지정** | `s_cfg.stepper_pins[3]` | 드라이버 IN4 |
| ADC 가변저항 | 아날로그 입력 | ADC | **미지정** | `s_cfg.adc.adc/channel/pcc_index` | Vref/전압 범위/실제 ADC 채널 확인 |
| OLED SDA | 양방향 | LPI2C | **기본 코드: PTA2, ALT3** | `s_cfg.oled_port.sda_*` 또는 기본 드라이버 | `custom_oled_port=0`이면 LPI2C0 기본 설정 |
| OLED SCL | 출력 | LPI2C | **기본 코드: PTA3, ALT3** | `s_cfg.oled_port.scl_*` 또는 기본 드라이버 | `custom_oled_port=0`이면 LPI2C0 기본 설정 |
| LCD RS | 출력 | GPIO, HD44780 4bit 전제 | **미지정** | `LCDHD44780Config.rs` | LCD 모델이 HD44780 호환 병렬인지 먼저 확인 |
| LCD E | 출력 | GPIO | **미지정** | `LCDHD44780Config.enable` | 병렬 LCD인 경우 |
| LCD D4 | 출력 | GPIO | **미지정** | `LCDHD44780Config.data[0]` | 병렬 LCD인 경우 |
| LCD D5 | 출력 | GPIO | **미지정** | `LCDHD44780Config.data[1]` | 병렬 LCD인 경우 |
| LCD D6 | 출력 | GPIO | **미지정** | `LCDHD44780Config.data[2]` | 병렬 LCD인 경우 |
| LCD D7 | 출력 | GPIO | **미지정** | `LCDHD44780Config.data[3]` | 병렬 LCD인 경우 |
| LCD RW | 외부 배선 | GND (4bit Write-only) | **MCU 핀 아님** | `lcd_hd44780.h` 주석 | I2C 백팩 LCD라면 별도 연결 방식 필요 |
| LED | 출력 | GPIO | **미지정** | `s_cfg.led_gpio.port/gpio/pin/active_high` | 500ms 간격 토글, 모의 동작 전용 |
| 버튼 | 입력 | GPIO + PORT IRQ | **미지정** | `s_cfg.button_gpio.port/gpio/pin/active_low/internal_pullup` | IRQ 전달 함수 연결 필요 |
| LPIT Tick | 내부 | LPIT0 | **외부 IO 핀 없음** | `s_cfg.timer.tick_channel` | 1ms 시스템 시간 |
| LPIT Trigger 타이머 | 내부 | LPIT0 | **외부 IO 핀 없음** | `s_cfg.ultrasonic.trigger_timer_channel` | TRIG 펄스 종료 |
| LPIT Stepper 타이머 | 내부 | LPIT0 | **외부 IO 핀 없음** | `s_cfg.stepper.timer_channel` | Stepper step 주기 |

**주의:** 위의 OLED PTA2/PTA3는 `src/oled_port_s32k144.c`의 **소프트웨어 fallback 기본값**이다. 실제 S32K144 보드·실습 확장보드에서 해당 핀이 OLED로 연결되었는지는 아직 확인하지 않았다.

## 3. 소스에 존재하는 유일한 구체적 OLED 기본 배치

`src/oled_port_s32k144.c`의 `OLED_PortInit()` 내부, 사용자 설정을 넣지 않았을 때:

```c
cfg.bus = LPI2C0;
cfg.bus_pcc_index = PCC_LPI2C0_INDEX;
cfg.bus_clock_pcs = 6u;

cfg.sda_port = PORTA;
cfg.sda_port_pcc_index = PCC_PORTA_INDEX;
cfg.sda_pin = 2u;
cfg.sda_alt = 3u;

cfg.scl_port = PORTA;
cfg.scl_port_pcc_index = PCC_PORTA_INDEX;
cfg.scl_pin = 3u;
cfg.scl_alt = 3u;
```

OLED 기본 통신 주소는 `src/header/oled.h`의 `OLED_I2C_ADDR=0x3C`이다. 실물 모듈에 따라 `0x3D`일 수도 있으므로 하드웨어를 확인해야 한다.

## 4. FTM·LPIT 배치 규칙

`main_all_test.c`의 `validate_mapping()`과 주변장치 소스 기준으로 반드시 지켜야 하는 조건:

1. `s_cfg.servo.ftm != s_cfg.ultrasonic.ftm` — Servo PWM과 Echo Capture는 **서로 다른 FTM 인스턴스** 사용.
2. `s_cfg.timer.tick_channel`, `s_cfg.stepper.timer_channel`, `s_cfg.ultrasonic.trigger_timer_channel` — **서로 다른 LPIT 채널** 사용.
3. Echo 입력에 해당하는 실제 FTM channel pair IRQ를 `MP_TERP_AllTestEchoCaptureIrq()`로 전달.
4. 버튼의 실제 PORTx IRQ를 `MP_TERP_AllTestButtonPortIrq()`로 전달.
5. 위 IRQ 전달 함수는 **벡터 핸들러를 자동 등록하지 않는다.** 실제 S32DS startup의 IRQ 이름과 중복 사용 여부를 확인한다.

이전 문서에 나온 `Tick CH3 / Stepper CH0 / Trigger CH1`은 **배정 예시일 뿐 현재 설정된 값이 아니다.**

## 5. 설정해야 하는 구조체 필드 체크리스트

`src/board_config_user_template.c`의 `MP_TERP_GetBoardConfig(BoardSystemConfig *cfg)`를 기준으로, 현 시점에는 다음 필드를 **실제 보드 회로도/핀 배선에 맞게 채워야 한다**.

```c
/* 아래는 필드 이름 확인용이다. 실제 핀·숫자를 추측해 넣지 않는다. */
cfg->timer;              /* LPIT PCS, functional clock, Tick channel */
cfg->servo;              /* PWM FTM, channel, ALT, port/pin, pulse/angle */
cfg->ultrasonic;         /* Trigger GPIO, Echo FTM, IRQ, clock, timeouts */
cfg->stepper_pins[0];    /* IN1 GPIO */
cfg->stepper_pins[1];    /* IN2 GPIO */
cfg->stepper_pins[2];    /* IN3 GPIO */
cfg->stepper_pins[3];    /* IN4 GPIO */
cfg->stepper_delay;      /* 유효한 delay callback 필수 */
cfg->stepper_mode;       /* FULL/HALF Step */
cfg->stepper;            /* LPIT, period_us, output steps per revolution, range */
cfg->adc;                /* ADC 인스턴스, 채널, Vref */
cfg->oled_port;          /* 기본 LPI2C를 사용하지 않는 경우 */
cfg->custom_oled_port;   /* 0이면 위 OLED 기본 핀 설정 사용 */
cfg->led_gpio;           /* LED port/GPIO/pin/polarity */
cfg->button_gpio;        /* 버튼 port/GPIO/pin/polarity/pull-up */
cfg->use_gpio_led = 1u; 
cfg->use_gpio_button = 1u;
cfg->lcd_write;          /* 실제 LCD 쓰기 callback */
cfg->user;               /* LCD 쓰기 callback의 문맥 */
```

또한 `MP_TERP_AllTestLCDInit()`은 실제 LCD 인터페이스에 맞게 구현해야 한다. 기본 템플릿은 이 함수에서도 `false`를 반환한다.

## 7. 실기기에서 반드시 확인해야 할 사항

- 현재 **Servo와 초음파 센서가 서로 독립적으로 장착**되어 있다. 이 구성에서 Servo 명령 각도를 초음파 측정 방향으로 간주하면 물리적으로 잘못된 2D 레이더 좌표가 만들어진다. `main_all_test.c`는 그래서 고정 방향 거리 측정과 Servo 수동 테스트를 분리한다.
- Servo 초기화는 초기 위치를 향한 PWM을 곧바로 낼 수 있으므로 **초기 기계 동작 가능성**에 대비한다.
- Stepper는 물리적으로 원점을 확인한 후에만 디버거에서 `g_all_stepper_home_confirm=0x484F4D45`를 설정한다.
- 초음파 Echo의 최대 HIGH 전압이 MCU 핀 입력 정격을 넘으면 **직접 연결하지 않는다.**
- 모터를 MCU GPIO에 직접 연결하지 않는다. 실제 드라이버·외부 모터 전원·공통 GND를 확인한다.
- LCD는 실물 제품이 HD44780 4bit 병렬인지, I2C 백팩인지 확인한다.
- 소스가 컴파일되어도 실제 핀 배치/전압/클록/IRQ가 맞았다는 뜻은 아니다.
