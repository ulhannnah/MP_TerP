# MP_TerP 기능별 세부 명세 및 하드웨어 자원 할당 v0.1

- 작성 기준: 2026-11-20
- MCU: NXP S32K144 (ARM Cortex-M4F)
- 보드: S32K144EVB + 점퍼 연결형 수업 실습 확장 보드
- 소스 작업 폴더: `D:\WorkSpace\MP_TerP` (`src/`, `src/header/`, `docs/`)
- S32 Design Studio 프로젝트: 별도 위치에서 관리
- 구현 방식: 기능별 C/H 분리, 최소 `main.c`, 인터럽트 + 메인 루프 협업

> **상태 정의**: **기존 코드** = 업로드된 라이브러리에서 확인된 설정; **후보** = 핀/채널 배정 제안; **TBD** = 하드웨어·보드 자료 또는 실제 실험 후 확정. 후보를 확정된 실제 점퍼 연결도로 사용하지 않는다.
>
> **안전 범위**: 발사는 LED/릴레이를 통한 표시 시뮬레이션에 한정하며 실제 발사 장치를 연결하지 않는다.

## 3. 타이머·인터럽트·코어 자원 배정

| 자원           | 전담 목적                  | ISR / 메인 루프 역할                            | 상태      |
| -------------- | -------------------------- | ----------------------------------------------- | --------- |
| `FTM1_CH1`   | 서보 PWM                   | PWM 하드웨어 생성, 비교값은 메인에서 갱신       | 후보      |
| `FTM0_CH6`   | 초음파 Echo Input Capture  | ISR: 캡처값/상태 기록, 메인: 거리 계산          | 후보      |
| `LPIT0_CH0`  | 스텝 모터 타이밍           | ISR: 코일 패턴 **한 스텝** 출력           | 후보      |
| `LPIT0_CH1`  | 초음파 Trigger 종료 타이밍 | 짧은 ISR: GPIO 펄스 종료                        | 후보      |
| `LPIT0_CH2`  | 시스템 주기 이벤트         | ISR: 시간 관리/작업 플래그, 메인: 처리          | 후보      |
| `LPIT0_CH3`  | 예비                       | 미사용                                          | 예약      |
| PORT IRQ       | 버튼                       | ISR: 입력 이벤트만 기록                         | TBD       |
| `ADC0`       | 가변저항                   | 주기 측정/완료 이벤트; 확정 방식 TBD            | 후보      |
| `LPI2C0`     | OLED                       | 메인에서 화면 전송 (기존 Blocking), 추후 최적화 | 기존 코드 |
| eDMA / DMAMUX  | 화면 전송 최적화           | 확장 기능, 채널 TBD                             | 확장      |
| Cortex-M4 DSP  | 고정소수점 필터            | 메인에서 호출                                   | 예정      |
| Cortex-M4F FPU | 좌표·속도·예측 계산      | 메인에서 호출                                   | 예정      |
| DWT CYCCNT     | 실행 사이클 측정           | 프로파일러에서 사용                             | 예정      |
| WDOG           | 오류 감시                  | 선택적 추가                                     | 확장      |

> **모듈 소유권**: LPIT0 모듈 클록·공통 설정은 `timer_manager.c`가 한 번만 설정한다. ISR 분배/채널 점유를 중앙에서 관리해 각 드라이버가 타이머 전체를 재초기화하지 않도록 한다. FTM 역시 인스턴스별 소유자를 명확히 한다.
>
> **주의**: LPIT는 자동으로 Trigger GPIO 파형을 출력하는 것이 아니다. 짧은 초음파 Trigger 펄스 생성은 ISR 지터를 검증하거나 다른 출력 방식으로 변경해야 한다.

## 4. 기능별 명세

### 4.1 레이더 스캔

#### 하드웨어

- 서보 모터, 초음파 센서

#### 기능

- 30°~150° 왕복 스캔, 각도별 거리·시간 측정
- 서보 정착 후 초음파 측정, 경계각 중복 방지

#### 보드 하드웨어

- `FTM1_CH1 / PTA1`: 서보 PWM (후보)

#### 구현

- `ScanConfig`: 범위·간격·정착·Timeout

## 5. 파일 분리 및 초기화 소유권

```text
MP_TerP/
├── docs/
│   └── hardware_resource_map.md    # 이 문서를 복사하여 관리 가능
├── src/
│   ├── main.c
│   ├── app.c
│   ├── board_init.c                # 핀/클록/주변장치 초기화 책임
│   ├── timer_manager.c             # LPIT 채널 소유/ISR 분배
│   ├── scan_manager.c
│   ├── ultrasonic.c
│   ├── servo.c
│   ├── step_motor.c
│   ├── target_tracker.c
│   ├── oled.c
│   ├── ...
│   └── header/
│       ├── board_config.h
│       ├── resource_map.h
│       └── ...
├── simulation/
└── tests/
```

- `main.c`: `app_init()` / `app_update()`만 호출하는 최소 진입점.
- `board_init.c`: 클록, PORT Pin MUX 등 공통 초기화 **1회**.
- `timer_manager.c`: LPIT0 채널 배정 및 인터럽트 디스패치.
- 기능별 `.c`: 독립 기능/상태 머신, 가능한 경우 하드웨어 직접 접근 최소화.
- PC 시뮬레이션과 실기기 드라이버 구현을 분리하고 상위 C API는 공유.
- 위 파일 목록은 **생성 예정 구조**이며 이미 작성된 파일 목록을 의미하지 않음.
