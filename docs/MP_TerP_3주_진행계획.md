# S32K144 보드 실습 3주 계획

**12월 16일 발표 목표**는 초음파 센서를 30°~150°로 돌리면서 물체 최대 5개의 위치와 ID를 OLED에 보여 주는 것이다. 가변저항으로 물체를 선택하면 문자 LCD에 거리·각도·상태를 표시한다. 거리 평균은 일반 C와 DSP로, 화면 좌표는 정수와 FPU로 각각 계산해 같은 조건에서 걸린 시간을 비교한다. [보드에 올리는 코드와 실행 방법](./MP_TerP_Jun명세_3주_보드실습코드.md)

| 주차                          | 첫날 목표                                                                | 둘째 날이 있으면                                          |
| ----------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------- |
| **1주차 · 11/25~12/1** | 보드에서 프로그램을 실행하고 서보·초음파·OLED를 각각 확인한다.         | 가변저항, LCD, 버튼·LED, 스텝 모터를 하나씩 시험한다.    |
| **2주차 · 12/2~12/8**  | 배경을 저장한 뒤 물체 1개 → 2개 → 3개를 화면에 표시하고 ID를 확인한다. | 전체 앱을 올려 센서·화면·입력이 동시에 동작하는지 본다. |
| **3주차 · 12/9~12/15** | 물체 5개의 ID를 검증하고 DSP·FPU를 측정한다. 시연을 촬영한다.           | 실패한 배치를 다시 시험하고 발표를 리허설한다.            |

첫날은 **4시간**, 둘째 날은 가능한 주에 **2~3시간**으로 잡았다. **창준**은 S32DS에서 코드 올리기, 화면·입력 확인, 측정표를 맡는다. **팀원**은 배선, 센서·서보 위치, 줄자·각도기 실측을 맡는다. 한 사람이 코드를 올리는 동안 다른 사람은 다음 물체 배치를 준비하거나 사진을 찍는다.

## 1주차 · 부품이 각각 동작하는지 확인

**첫날 할 일**

1. **0~40분 · 보드에서 코드 실행.** 창준은 데이터 USB를 연결하고 기존 검사 코드를 `Debug_RAM`으로 올린다. F8로 실행해 디버거에서 PASS 값을 확인한다. 팀원은 부품 모델과 케이블이 꽂힌 위치를 사진으로 남긴다.
2. **40~100분 · 보드 시간과 서보 각도 확인.** Stage 1에서 보드의 시간값(Tick)이 1초에 약 1000씩 느는지 본다. Stage 2에서는 서보를 가운데부터 조금씩 움직인다. 가운데와 양쪽 끝에서 명령한 각도와 각도기로 잰 각도를 각각 적는다. 센서 방향도 서보와 함께 바뀌는지 본다.
3. **100~170분 · 초음파 거리 측정.** Stage 3에서 센서 앞에 평평한 물체를 놓고 가까운 곳, 중간, 먼 곳에서 **각 5회** 측정한다. 줄자로 잰 거리와 보드 값을 같이 적는다. 물체가 없는 방향에서 측정 실패가 뜨는 조건을 확인하고, 물체를 다시 놓으면 정상 거리로 돌아오는지 본다.
4. **170~240분 · OLED와 핀맵 확인.** 화면에 `OLED OK`와 점이 뜨는지 본다. 가변저항을 양 끝까지 돌렸을 때 나온 ADC 값과 LCD 모델·연결 방식을 적는다. 팀원은 센서를 서보에 고정하고 다음 주에 쓸 벽이나 배경판을 정한다.

**둘째 날이 있으면** LCD 두 줄, 가변저항으로 ID가 바뀌는 경계, 버튼을 짧게·길게·연속으로 눌렀을 때 LED가 어떻게 표시되는지 확인한다. 팀원은 스텝 모터의 기준 위치를 표시하고 실제 이동각을 잰다. 첫날에 동작하지 않은 부품이 있으면 그 부품부터 다시 확인한다.

**마치기 전에 남길 것**은 PASS 화면, OLED 사진, 실제 핀맵, 서보 각도 3쌍, 거리 측정 15회와 무효 횟수다. 이 자료로 다음 주에 같은 배선을 재현할 수 있어야 한다.

핀을 정할 때 `PTA1/FTM1_CH1`, `PTE8/FTM0_CH6`은 Jun 명세에 적힌 후보다. 보드 커넥터의 실제 핀과 전압을 확인한다. OLED의 기존 기본 연결은 `PTA2/SDA`, `PTA3/SCL`이다. 서보와 Echo는 서로 다른 FTM을, 보드 시간과 Trigger는 서로 다른 LPIT 채널을 쓴다. Echo 파형이 있는데 거리가 계속 무효면 인터럽트 함수 연결, NVIC 활성화, 핀 기능 설정(ALT)을 확인한다. [보드 투입 체크리스트](https://github.com/ulhannnah/MP_TerP/blob/33ed0f1508e5aa252698dd087d9a52e856d058bb/docs/20261125_S32K144_보드_투입_체크리스트.md)

## 2주차 · 빈 배경을 저장하고 물체 1~3개 확인

**첫날 할 일**

1. **0~45분 · 배경 저장.** 센서가 도는 방향과 OLED에 그려지는 방향을 대조한다. 보드에 3개 모드를 올리고, 시험 물체를 치운 채 시작한다. 센서가 한쪽 끝에서 반대쪽 끝까지 움직이는 **첫 편도**에 배경 거리를 저장한다. 다음 편도에는 배경만 둔 상태에서 후보 수와 유효 측정 칸 수를 적는다.
2. **45~105분 · 물체 1개와 2개 비교.** 물체 한 개를 왼쪽·가운데·오른쪽에 놓고 줄자 거리와 보드 거리를 비교한다. 두 개는 충분히 띄워서 놓고, 거리는 그대로 두면서 두 물체 사이의 각도만 줄인다. 처음으로 하나처럼 표시된 배치를 찍어 둔다.
3. **105~155분 · ID 선택과 화면 확인.** 가변저항을 돌리면서 OLED에서 강조된 물체와 LCD의 ID가 같이 바뀌는지 본다. 물체 하나를 치운 뒤 LCD의 표시를 관찰한다. `NEW`는 새 물체, `TRACKING`은 추적 중, `MISSED`는 이번 스캔에서 놓침, `LOST`는 유실 판정, `EMPTY`는 기록이 비어 있는 상태다.
4. **155~210분 · 거리 평균과 좌표 확인.** 같은 각도에서 최근 거리 3개를 평균 내도록 설정한다. 첫 편도부터 다시 실행해서 물체를 놓고 몇 편도 뒤 값이 안정되는지 적는다. DSP와 FPU 설정을 차례로 확인해 거리 필터의 실행 시간과 선택한 물체의 X·Y 값을 읽는다.
5. **210~240분 · 물체 3개 확인.** 세 물체가 구분되는 배치를 기록하고 다음 주에 쓸 다섯 곳을 A~E로 표시한다. 사용한 ELF 파일명과 설정, 바뀐 배선을 같이 남긴다.

**둘째 날이 있으면** 기존 전체 앱(Stage 5)을 별도 `Debug_RAM` 구성으로 올린다. 먼저 실제 배선과 센서·서보 결합, 모터 기준 위치를 확인한다. 이후 스캔하면서 OLED·LCD와 가변저항·상태 LED가 같이 동작하는지 본다. 화면이 바뀔 때 초음파 측정이 더 자주 누락되는지도 적는다. 하루만 실습한 주에는 이 확인을 3주차 첫 40분에 한다.

**마치기 전에 남길 것**은 물체 1·2·3개의 편도별 후보 수와 ID, 두 물체가 하나로 보인 간격, OLED·LCD 사진, A~E의 위치다. [코드 실행 순서와 디버거에서 볼 값](./MP_TerP_Jun명세_3주_보드실습코드.md)

## 3주차 · 5개 물체를 검증하고 발표 자료 만들기

**첫날 할 일**

1. **0~40분 · 시연 환경 확정.** 팀원은 표시 장치와 전체 앱 동작을 확인한다. 창준은 촬영에 쓸 코드 버전(커밋), 배선 사진, `Debug_RAM` 설정을 기록한다.
2. **40~110분 · 같은 배치로 3개 모드와 5개 모드 비교.** 3개 모드에서 A~E의 물체 5개를 놓고 후보 수와 새로 갱신된 ID 수를 기록한다. 5개 모드로 다시 올린 뒤 물체를 치우고 배경을 먼저 저장한다. 같은 위치에 4개, 이어 5개를 놓는다. 배치가 끝난 다음 시작하는 **연속 5편도**의 ID·각도·거리를 적는다. 보드를 다시 실행해 같은 결과가 나오는지 한 번 더 확인한다.
3. **110~160분 · 물체가 사라졌다 돌아오는 경우 확인.** 물체 하나를 옮기거나 가렸다가 다시 놓는다. 두 물체가 하나로 잡히거나, ID가 서로 바뀌거나, `LOST`로 바뀌는 순간을 적는다. **한 편도에서 잡힌 최대 수**와 **연속 5편도에서 유지된 수**를 각각 기록한다.
4. **160~205분 · 계산 시간 비교.** 같은 배치와 평균 샘플 수, 같은 빌드 설정에서 일반 C와 DSP를 각각 실행한다. 같은 물체의 각도와 거리로 정수 좌표와 FPU 좌표도 비교한다. 평균·최대 실행 사이클, 좌표 차이(mm), 편도 시간(ms)을 기록한다. 발표에는 보드에서 잰 값을 사용한다.
5. **205~240분 · 촬영과 제출 준비.** 빈 배경 → 물체 배치 → 가변저항으로 ID 선택 → OLED·LCD 순서로 찍는다. 발표 자료에 실측표, 회로도, 프로그램 흐름도를 넣는다. **12월 16일에 제출할 PPT·실물 영상·실행한 소스**를 모으고 10분 발표 순서를 정한다.

**둘째 날이 있으면** 실패한 배치 하나를 같은 조건에서 재현한 뒤 각도 간격이나 거리 중 한 가지만 바꾼다. 팀원이 같은 ELF로 한 번 더 실행하고 영상을 보완한 뒤 발표를 리허설한다. 화면의 eDMA 전송과 WDOG 복구는 5개 시연이 안정되면 검토한다.

**5개를 잡았는지 보는 방법.** 한 편도는 30°→150° 또는 150°→30° 한 번이다. 연속 5편도에서 매번 `fresh=5`인지 보고, 물체 A~E에 같은 ID가 계속 붙는지 거리와 각도로 확인한다. `id_mask=0x1F`는 ID 1~5가 모두 갱신됐다는 뜻이다. A와 B의 ID가 서로 바뀌어도 이 값은 같을 수 있다. 화면에 잠깐 남아 있는 이전 ID는 이번 편도의 갱신 수에 넣지 않는다. 연속 5편도는 팀에서 쓰도록 제안한 기준이다.

| 모드·코드 버전 | 배치와 편도 번호 | 유효/수신 칸 | 후보 수/갱신 ID 수 | A~E별 ID·각도·거리 | 유실·ID 교환 | 배선·사진 |
| --------------- | ---------------- | ------------ | ------------------ | -------------------- | ------------- | ---------- |
| 실측 후 작성    |                  |              |                    |                      |               |            |

실험을 다 끝내지 못했다면 발표에서 확인한 범위를 명확히 적는다. 독립 시험과 전체 앱 시험은 각각 어떤 기능을 실행했는지 적고, 물체가 합쳐진 경우에는 실제 검출 수와 간격을 넣는다. 명령 생성만 확인한 항목은 빌드 결과로, 보드에서 잰 수치는 성능 측정값으로 적는다.

| 13 핵심        | FPU 위치 계산         | 같은 관측의 X·Y를 정수와 FPU로 계산한다. 저장소의 속도·예측 함수는 실제 추적에 연결됐는지도 따로 확인한다.                    |
| 14 확장        | eDMA 화면 전송        | 기존 OLED 전송 시간을 잰다. eDMA 전송 비교는 핵심 시연을 마친 뒤 검토한다.                                                      |
| 15 핵심        | 실험값 기록           | 편도 번호, 유효 거리 수, 이번 편도에서 갱신한 ID, 실행 사이클을 같은 설정과 함께 적는다.                                        |
| 16 확장        | 오류에서 복구         | 센서 응답 없음, 물체 유실, 화면 오류를 확인한다. WDOG 자동 복구는 확장 항목이다.                                                |
