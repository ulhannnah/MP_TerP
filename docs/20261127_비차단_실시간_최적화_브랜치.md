# MP_TerP — 비차단 실시간 최적화 브랜치 (2026-11-27)

- 브랜치: `opt/nonblocking-edma-20261127`
- 원본 기준: `final/radar-system-20261126` / `6dbc4909d40e0602bdab64bc7c4cfb6ddf546736`
- 목적: 기존 검증된 입출력 핀과 구동 기능을 유지하면서 Main foreground의 Worst-Case Execution Time을 줄이고, CPU의 OLED 대기 시간을 없애는 것
- **현재 단계:** 1차 비차단 LPI2C + OLED Dirty Page + 1ms 협력형 App FSM + Relay LPIT one-shot. **eDMA는 선택형 코드로 구현했으나 실물 검증 전이며 기본 OFF**
- 안전: 실제 릴레이 코일은 GPIO에 직접 연결하지 말 것. PTC4(SWD_CLK)/PTC5(JTAG)는 건드리지 않으며 외부 버튼 PTC8/PTC9 유지

## 변경 사항

| 기능 | 최종 기준 브랜치 | 최적화 브랜치 |
|---|---|---|

| OLED 전송 | `OLED_Update` 동기 호출 | 기본: `OLED_RequestUpdate`+`OLED_Service`에서 MTDR 1개 이하 공급 / 실험: eDMA TX TCD 자동 전송 |

### OLED 전송 API

- `OLED_Init()`은 초기 부팅에서 기존의 *동기식* OLED 초기화 및 전체 Clear 전송을 유지한다.
- Stage5의 App `oled_flush`는 `OLED_Update()`가 아니라 `OLED_RequestUpdate()`를 호출한다.
- `BoardSystem_Update`는 매 반복마다 `OLED_Service(TimerManager_GetTickMs())`를 호출한다.
- `OLED_Service`는 SSD1306의 `0x21`(Column address) 및 `0x22`(Page address) 설정 후 각 Page 내 변경된 최소~최대 열 구간만 보낸다. 예: 1열만 바뀌면 1B, 10열과 20열이 바뀌면 11B 전송.
- 전송 중 프레임버퍼는 계속 변경 가능하나, Tx Page 스냅샷 `s_page_data`는 완료 전까지 변경되지 않는다.
- 화면이 변화 없으면 I2C 데이터 전송을 생략한다. 열 구간은 연속 전송이며, 여러 조각으로 나누어 버스 오버헤드를 늘리지 않는다.
- **기본 폴링 모드**의 `OLED_PortAsyncService`는 TDF를 한 번 읽고 공급 가능할 때만 MTDR 최대 한 워드를 쓴다. **eDMA 모드**는 eDMA가 LPI2C MTDR에 데이터를 자동 공급하고 전경은 DONE+SDF를 확인한다. `for` busy-wait는 없다.

**주의:** 기본 설정은 메인 루프 반복이며 WFI는 OFF. `MP_TERP_OLED_EDMA_ENABLE=1`인 경우에만 `MP_TERP_IDLE_WFI_ENABLE=1`을 추가하여 WFI를 실험할 수 있다. 전력/CPU 사용률 개선은 실측 전까지 주장하지 말 것.

### LPIT 자원

| 채널 | 담당 |
|---|---|
| CH0 | 28BYJ Stepper 스텝 |
| CH1 | Ultrasonic Trigger 10µs |
| CH2 | 1ms system tick |
| CH3 | 200ms Active-High Relay one-shot 종료 |

Relay 타이머는 시작 *직후* HIGH로 출력되므로 설정한 200ms보다 몇 CPU cycle 짧을 가능성이 있다. 실측 검증이 필요하며 foreground fallback도 유지한다.

### S32DS Expressions 확인

- `g_stage_state == 2`, `g_stage_error == 0` (부팅/정상 실행)
- `g_stage_oled_pages_sent`: 실제 전송을 완료한 Page 업데이트 횟수 (데이터량은 1~128B 가변)
- `g_stage_oled_pages_skipped`: 이전 전송 이미지와 동일하여 생략한 Page 횟수
- `g_stage_oled_data_bytes`: 실제 화면 데이터 전송량 (변경 열 구간의 합, `128 * pages_sent`가 아님)
- `g_stage_oled_errors`: LPI2C 오류/전송 timeout 누적
- `g_stage_oled_busy`: 현재 화면 변경분 전송 예약/진행
- `g_stage_oled_transport_mode`: 0=기본 CPU 비차단 폴링, 1=옵션 eDMA 초기화 성공 (10ms마다 갱신)
- `g_stage_update_cycles_last`, `g_stage_update_cycles_max`: DWT 기준 한 번의 `BoardSystem_Update` 경과 Cycle. CPU clock 80MHz이면 `cycles / 80` ≈ µs. ISR 선점 시간도 포함. 최대값은 매 호출 관측하고, 디버거 변수 갱신은 10ms마다 한다.
- `g_stage_relay_pulses`: 유효한 소프트웨어 조준 완료 이후 Relay pulse 횟수

### 기존 Stage5 모드 주의

기본 모드는 센서가 Servo에 기계적으로 결합되지 않았다고 가정하는 1D 진단이다. 외부 가변저항으로 `30~150°` 수동 조준각을 고르고 AIM 버튼으로 Stepper를 회전한다. 실제 표적 각도를 추적하는 기능은 `MP_TERP_CONFIRM_COUPLED_GEOMETRY`를 명시적으로 켜고 물리 결합을 확인해야 한다.

### 보드 확인 절차

1. **기존 최종 브랜치가 정상 작동함을 확인한 경우에만** 이 브랜치를 별도로 Clean/Build.
2. 모터/릴레이 부하를 분리한 상태로 S32DS Flash & Debug 및 DWT/OLED 진단 변수 확인.
3. Servo, Ultrasonic, Stepper, 두 외부 버튼, ADC를 순차적으로 연결해 구동/IRQ 검증.
4. OLED가 150ms 주기와 맞게 갱신되며, 변화가 없을 때 `pages_sent`가 증가하지 않는지 확인.
5. LCD 정상 갱신과 Relay pulse 실제 길이를 Logic Analyzer/오실로스코프로 측정.
6. CPU 전송과 향후 eDMA 전송의 **전체 I2C bus time, foreground latency, 최대 업데이트 cycles, button latency, jitter**를 비교할 것.

## 2차 최적화 수정 — 변경 열 구간 + 진단 오버헤드 축소

- 2026-11-27: 1차 Dirty Page 설계를 보존하면서 각 페이지에서 수정된 최초 열~마지막 열만 전송한다. 단일 바이트 변경은 128B 대신 1B이고, 떨어진 두 열은 이를 포함하는 연속 구간만 전송한다.
- 128B 불변 스냅샷을 계속 사용한다. STOP 성공 뒤 실제 전송 구간만 Shadow에 반영하고, 후속 요청이 있으면 다시 변경 여부를 비교한다.
- `main_stage.c`에서 `BoardSystem_Update`·OLED 서비스 호출은 그대로 유지한다. 다수의 `volatile` S32DS Expressions 스냅샷은 10ms에 1회로 제한하고 최대 업데이트 사이클은 매 호출 관측한다.
- 호스트 테스트 통과가 S32DS ARM 빌드나 SSD1306 실물 검증을 대신하지 않는다. eDMA는 선택형으로 구현하였고 디폴트 OFF이며, OLED/LCD 부팅 초기화는 여전히 동기식이다.

## 3차: 선택형 eDMA 구현 (호스트 검증, 실물 미검증)

- `-DMP_TERP_OLED_EDMA_ENABLE=1`: eDMA CH0을 OLED 전용으로 예약; DMAMUX0 source 45(LPI2C0 TX 요청), TCD에서 SRAM 32-bit command/data words → LPI2C0 MTDR 32-bit 쓰기, SOFF=4, DOFF=0, NBYTES=4, major count=data length+3 (START/control/STOP), DREQ=1.
- DMA 완료 DONE만으로 SSD1306 표시를 확정하지 않는다. **DMA DONE + LPI2C SDF(STOP)** 두 조건이 일치해야 Snapshot 내용을 displayed Shadow에 커밋한다. 전송 장애나 200ms 타임아웃 시 DMA 요청을 끄고 LPI2C 재초기화 후 250ms 재시도한다.
- `-DMP_TERP_OLED_EDMA_ENABLE=0` 또는 심볼 미정의: 기존 CPU 비차단 FIFO 서비스 유지. 별도 빌드 경로로 빠르게 롤백할 수 있다.
- `-DMP_TERP_IDLE_WFI_ENABLE=1`은 **eDMA=1과 함께만** 사용 가능. 1ms LPIT Tick이 Cortex-M4F를 깨우는 전력 실험용이며 첫 현장 테스트에서는 OFF 권장.
- **주의:** TCD0 및 DMAMUX 채널0의 독점 사용을 전제로 하므로 다른 DMA 클라이언트와 공유할 수 없다. 실제 하드웨어/SDK 레지스터 호환성, I2C 파형 및 전력 감소는 보드 시험 전 미검증.
- eDMA 모드의 전경 전송 완료 처리는 **폴링**이고 DMA IRQ는 사용하지 않는다. CPU가 전송 바이트를 직접 제공하지 않는 것과 완료 통지에 IRQ를 쓰는 것은 별개이다.
