# MP_TerP S32K144 핀·타이머 자원 배치 및 단계별 실행 가이드

작성일: 2026-11-24 · 대상 브랜치: `jun_GPT` · 보드 최초 시험: 2026-11-25

> **중요:** 아래 표의 빈칸은 누락이 아니라 **확인되지 않은 핀**이다. 실제 MCU 보드/확장보드/배선의 회로도와 실물을 확인하기 전에는 MCU 포트나 ALT 기능을 추측해서 기입하지 않는다.

## 1. 실제 장착 구조 및 중요한 설계 제한

원래 레이더 알고리즘은 다음 구조를 가정했다.

```text
서보가 회전 → 서보 위에 장착된 초음파 센서도 회전
             ↓
           서보 각도 θ와 거리 d가 동일 방향 측정
             ↓
           (θ,d)를 레이더 표적 좌표로 사용
```

그러나 실물 장착은 **서보와 초음파 센서가 각각 보드에 고정되어 독립적으로 움직이는 구조**로 보고됐다.

```text
고정 초음파 센서  ──> 고정 방향으로 거리 d 측정
서보 모터        ──> 별도의 축에서 각도 θ 명령
                    (두 값 사이에 물리적인 방향 대응 없음)
```

따라서 고정 초음파 거리 `d`에 독립적인 서보 각도 `θ`를 붙여 레이더 스캔을 만드는 것은 **물리적으로 잘못된 좌표**다. 두 장치를 사람이 같은 방향으로 움직이도록 손으로 조정하더라도 각도 정합·시간 동기·오프셋을 측정하지 않으면 2D 레이더 검증으로 인정할 수 없다.

실물에서 가능한 선택지:

1. **최선**: 센서를 회전 축에 실제 고정해 방향을 같이 움직이게 한다. 기구적 정렬 각도와 영점 보정 필요.
2. **수동 스캔 벤치**: 초음파 센서를 손으로 움직여 각도를 표시한 눈금/지그에서 측정한다. 실제 각도는 **별도 기록/입력**하고 서보 각도를 진실값으로 쓰지 않는다. 현재 펌웨어에는 수동 각도 입력을 받는 경로는 아직 없다.
3. **센서 고정 유지**: 1차 실물 시험은 1D 거리 센서 + 독립 서보 검증으로 제한한다.
4. **가상 통합 벤치**: 아래 Stage 4에서 생산용 C `App`에 가상 Echo를 넣어 스캔·검출·Tracker를 검증한다. **센서 측정의 실물 정확도 검증이 아님**.

## 2. 핀 및 하드웨어 연결 확인표

| 기능 | 인터페이스/코드 설정 | 실제 MCU 핀 | 핀 ALT/채널 | 센서/배선 점검 |
|---|---|---|---|---|
| CPU 클록 | `clocks_and_modes.c` | 내부 | SOSC/SPLL | 실제 8MHz 외부 오실레이터 지원 여부 확인 |
| 시스템 Tick | `timer.tick_channel` | 내부 | LPIT0 CH__ | 타이머 기능 클록/PCS와 Hz 확인 |
| 서보 신호 | `servo.port, pin, pin_alt, ftm, channel` | PT__ | FTM__ CH__ ALT__ | 서보 신호 논리 레벨/실제 펄스폭 |
| 서보 전원 | 외부 전원 | 해당 없음 | 해당 없음 | V+__, Imax__, GND, MCU 직결 금지 |
| 초음파 Trigger | `ultrasonic.trigger_port, trigger_gpio, trigger_pin` | PT__ | GPIO | TRIG HIGH 레벨, 펄스폭 |
| 초음파 Echo | `ultrasonic.echo_port, echo_pin, echo_pin_alt` | PT__ | FTM__ CH__ ALT__ | Echo 최대 전압 및 레벨 시프터 |
| 스텝 모터 IN1 | `stepper_pins[0]` | PT__ | GPIO | 드라이버 핀 IN1 |
| 스텝 모터 IN2 | `stepper_pins[1]` | PT__ | GPIO | 드라이버 핀 IN2 |
| 스텝 모터 IN3 | `stepper_pins[2]` | PT__ | GPIO | 드라이버 핀 IN3 |
| 스텝 모터 IN4 | `stepper_pins[3]` | PT__ | GPIO | 드라이버 핀 IN4 |
| 스텝 타이머 | `stepper.timer_channel` | 내부 | LPIT0 CH__ | Tick/Trigger와 별도 |
| ADC 가변저항 | `adc.adc, adc.channel` | PT__ | ADC__ SE__ | Vref, 최대 입력전압 |
| OLED SDA | `oled_port.sda_port/sda_pin` | PT__ | LPI2C__ ALT__ | I2C pull-up 및 논리 레벨 |
| OLED SCL | `oled_port.scl_port/scl_pin` | PT__ | LPI2C__ ALT__ | I2C pull-up 및 논리 레벨 |
| 텍스트 LCD RS | `LCDHD44780Config.rs` | PT__ | GPIO | **실물 모델/인터페이스 확인** |
| 텍스트 LCD E | `LCDHD44780Config.enable` | PT__ | GPIO | |
| 텍스트 LCD D4~D7 | `LCDHD44780Config.data[0..3]` | PT__ ×4 | GPIO | HD44780 4-bit 병렬 시에만 |
| 텍스트 LCD RW | 연결 | GND | 고정 LOW | 위 병렬 모드에서만 |
| LED | `led_gpio` 또는 `led_write` | PT__ | GPIO | 시뮬레이션 출력 전용, 직렬 저항 |
| 버튼 | `button_gpio` | PT__ | PORTx IRQ | Pull-up/엣지 설정 |

**확인된 코드 기본 설정:** `custom_oled_port == 0`일 때 기존 OLED 포트 드라이버는 LPI2C0, PTA2/3를 사용한다. 이것은 **소프트웨어의 기본 배치**이지, 실제 보드에서 SDA/SCL에 연결되었다는 근거가 아니다.

### 자원 충돌 방지

| 공유 자원 | 배치 조건 |
|---|---|
| FTM | 서보 PWM과 Echo Input Capture는 **다른 FTM 인스턴스** |
| LPIT | Tick, 초음파 Trigger 펄스, Stepper 각기 다른 채널 |
| PORT/PT 핀 | OLED·LCD·서보·초음파·모터 드라이버·버튼이 중복 사용하지 않도록 배치 |
| FTM IRQ | Capture용 FTM 채널쌍 벡터는 SDK startup 파일과 정확히 일치해야 함 |
| Power | MCU, 센서, 모터의 전원/로직 레벨과 GND 연결을 확인 |

**LPIT 할당은 아직 최종 결정이 아니다.** 코드의 기존 예시로 `Tick=CH3, Stepper=CH0, Trigger=CH1` 조합이 있지만, 실제 보드와 다른 코드의 사용 상황을 확인하기 전에는 확정값으로 간주하지 않는다.

## 3. 단계 선택형 메인

기존 `src/main.c`는 항상 안전한 소프트웨어 Smoke Test이며, 핀 설정을 하지 않는다. 새로 추가된 `src/main_stage.c`는 **빌드 시 심볼만 변경하여** 단계별 실행한다.

- `MP_TERP_STAGE_MAIN`: 스테이지 메인 활성화 (이때 기존 `main.c`는 `main()`을 정의하지 않음).
- `MP_TERP_STAGE=숫자`: Stage 1~5 중 하나 지정.
- `MP_TERP_USE_EXAMPLE_MAIN`은 이때 **정의하지 않는다**.
- S32DS의 프로젝트 `Symbols`에서 모드를 바꾸고 **Clean / Build / Flash**한다. 하나의 펌웨어에서 스테이지를 자동 진행하지 않는다.

| 모드 | 빌드 심볼 | 실제로 활성화되는 것 | 실물 위험·조건 |
|---|---|---|---|
| **0. 기본 진단** | 스테이지 심볼 **둘 다 미정의** | 기존 테스트 `main.c`만 | GPIO/모터 미접촉 |
| **1. Clock + Tick** | `MP_TERP_STAGE_MAIN`, `MP_TERP_STAGE=1` | 클록 초기화 + 1ms LPIT | 실제 클록 소스 확인 |
| **2. Servo 독립** | 위 + `MP_TERP_STAGE=2` | 클록·Tick + 서보 PWM 1개 | **초기값 고정**, 자동 스캔 안 함 |
| **3. 초음파 독립** | 위 + `MP_TERP_STAGE=3` | 클록·Tick + Trigger/Echo | Echo 전압 보호, IRQ 필요 |
| **4. 가상 C App 벤치** | 위 + `MP_TERP_STAGE=4` | 가상 서보·Echo + 실제 App/C Tracker | **보드 주변장치 미사용** |
| **5. 전체 실제 앱** | 위 + `MP_TERP_STAGE=5`, `MP_TERP_CONFIRM_COUPLED_GEOMETRY` | `BoardSystem_Init/Update` | **실제 방향 연동·원점·핀맵 확인 전 금지** |

Stage 4는 소스상 실물 핀·FTM 초기화를 호출하지 않는 가상 벤치지만, MCU에 실행되는 정적 `App` 자체의 SRAM 소비와 DSP·알고리즘 경로를 검증한다. 모든 실물 메커니즘은 불활성화한다.

### Stage 2: 수동 서보 각도 변경

Stage 2는 초기 위치 **고정**이다. 안전한 펄스폭·기구 한계를 확인한 뒤에만 디버거 Expressions 창에서

```text
g_stage_servo_request_mdeg
```

에 밀리도(예: **90000 = 90°**)를 써서 해당 각도로 이동시킨다. 유효 범위를 벗어나면 움직이지 않고 `g_stage_error=21`이 된다. **절대로 자동 왕복하지 않는다.**

### Stage 3: 독립 고정방향 초음파

- 약 100ms 간격으로 Trigger를 시도한다.
- `g_stage_last_mm`: 최근 측정 거리(mm)
- `g_stage_samples`: 결과 건수
- `g_stage_valid`, `g_stage_invalid`: 유효/무효 측정 건수
- **FTM 캡처 IRQ 벡터**가 `MP_TERP_StageEchoCaptureIrq()`를 호출하도록 사용자의 S32DS startup 구조에 맞춰 연결해야 한다. 이 IRQ 훅은 자동 벡터 등록이 아니다.
- 고정방향 거리 측정값이므로 **레이더 각도 데이터로 해석하지 않는다**.

### Stage 4: 동작 경로 가상 벤치

서보 위치에 따라 가상 반사 거리 2개를 생성한다. 초기 편도 스캔은 3000mm 빈 배경으로 보정하고, 그다음 편도 스캔부터 두 개 영역의 반사체를 생성한다.

실제 `App_Init`, `App_Update`, `RadarScan`, `RadarProcessing`, `TargetTracker`, `TargetSelector`, `AimController`의 흐름을 MCU 안에서 확인한다.

- `g_stage_frames`: 완료한 편도 스캔 수
- `g_stage_candidates`: 최근 검출 후보 수
- `g_stage_active_tracks`: 현재 활성 표적 수
- `g_stage_selected_id`: 가상 ADC로 선택한 ID (현재 1)
- `g_stage_tick_ms`: **가상 시각**, 실제 1ms 하드웨어 Tick이 아니다.

Stage 4의 CPU 속도나 실행 시각을 실제 센서의 시간 지연 검증에 사용하지 않는다. Stage 4에서는 OLED/LCD와 모든 물리 장치를 초기화하지 않는다.

### Stage 5: 전체 앱의 안전 게이트

`MP_TERP_CONFIRM_COUPLED_GEOMETRY`가 없으면 **실제 전체 앱을 초기화하지 않고** `g_stage_error=50`으로 남는다. 단순히 컴파일을 통과하기 위해 이 심볼을 정의하지 말 것.

정의 가능한 조건:

- 센서 빔 방향과 실제 스캔 각도의 대응이 확인됨.
- Echo 전압이 해당 MCU 입력 핀의 정격과 호환됨.
- Servo/Stepper 기계 한계 및 전원·드라이버 확인.
- MCU 클록, Timer, FTM, IRQ 채널 배치와 LCD/OLED가 검증됨.

현재 고정 초음파 + 별도 서보 구조라면 **Stage 5를 실행하면 안 된다**. 고정 센서의 거리만으로 2D 방위를 구할 수 없기 때문이다.

## 4. 보드 핀/클록 설정 제공 방식

Stage **1/2/3/5**에는 사용자 프로젝트에 다음 함수가 정확히 1개 필요하다.

```c
bool MP_TERP_GetBoardConfig(BoardSystemConfig *cfg);
```

이는 프로젝트의 실제 S32K144 회로와 배선이 확정된 다음 별도 `board_config.c`에서 구현한다. 초기 설정만 반환해도 되는 Stage 1과 달리 Stage 2는 `servo`, Stage 3은 `ultrasonic`, Stage 5는 **전체** 설정을 필요로 한다. 이 함수가 없으면 해당 모드는 **링크 에러**로 멈추도록 의도했다. 불확실한 핀을 임의로 사용할 수 없게 하기 위함이다.

별도의 정확한 물리 설정을 요구하지 않는 **Stage 4는 위 함수를 호출하지 않는다.**

### IRQ 연결 예제 (예시 이름만; startup 실제 IRQ명 확인)

```c
/* 반드시 실제 S32DS vector table에 존재하는 FTMx_Chy_Chz_IRQHandler로 변경 */
void FTMx_Chy_Chz_IRQHandler(void)
{
    MP_TERP_StageEchoCaptureIrq();
}
```

위는 벡터 연결의 의사 코드다. **그대로 컴파일하면 안 된다.** 해당 vector 이미 다른 드라이버에서 정의 중이면 중복 심볼을 만들지 말고 하나의 IRQ 소유 파일에서 분배해야 한다.

## 6. 내일 실행 순서

1. **Stage 0**: 기존 진단용 메인으로 `g_mp_terp_smoke_signature=0x50415353`, `result=0`, `stage=6` 확인.
2. 실물 보드/확장 보드 이름·MCU 패키지·회로도·전압 범위를 확인하여 2절 핀맵 작성.
3. **Stage 1**: 클록 및 LPIT 증가량 확인.
4. **Stage 2**: 서보 PWM부터 로직 분석기/오실로스코프로 확인, 그다음 좁은 각도로 수동 이동.
5. **Stage 3**: 초음파 Trigger/Echo 및 거리값 확인. 고정 방향 거리 센서로만 해석.
6. **Stage 4**: 가상 벤치로 앱 초기화·스캔·검출 확인 (실제 센서/모터 구동 없음).
7. ADC·OLED·LCD·Stepper는 실제 핀맵 확인 후 각각의 모듈 시험 소스를 추가로 구성한다. **Stage 1~4에 이들의 자동 실물 실행은 포함되지 않는다.**
8. 실제 센서 장착 구조와 각도 연동 방법이 해결된 뒤에만 **Stage 5**로 진입한다.

**안전 경계:** 레이더/Stepper를 이용한 모의 동작은 LED 표시로 제한한다. 실제 발사 장치나 고전력 구동기를 연결하지 않는다.

## 7. 검증 상태

이 문서와 Stage 메인 소스는 `jun_GPT`에 구현되어 있으나 **이 신규 스테이지 소스에 대한 S32DS 빌드 및 실제 디버거 실행 PASS는 아직 확보되지 않았다**. 기존 빌드·시뮬레이션 PASS를 이번 새 단계의 검증 결과로 대체하지 않는다.
